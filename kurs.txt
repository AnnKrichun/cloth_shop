    Моделі: у модуль потрібно додати не менше, ніж 5 нових моделей.
    Представлення: кожна модель повинна мати два базових представлення (tree, form) в обов'язковому порядку, та мати хоча б одне з наступних представлень (pivot, graph, kanban, search) в одній з додаваних моделей.
    Меню: модуль повинен мати власне меню верхнього рівня. Необхідно додати зображення для батьківського розділу меню.
    Наслідування: модуль повинен наслідувати та розширювати (або змінювати) функціонал якнайменше двох стандартних моделей.
    Візарди: необхідно додати тимчасову модель до модуля.
    Звіти: модуль повинен містити один друкований звіт.
    Демо дані: необхідно додати демо дані до модуля, що розробляється, якнайменше по 3 записи для кожної доданої моделі.
    Тести: модуль повинен мати тести, для цього бажано продумати декілька тест-кейсів та додати їх у модуль. Кожна додана модель повинна мати хоча б по одному тестовому методу.
    Права доступу:

        Додайте дві нові групи користувачів (User та Admin) до модуля, котрі повинні входити в одну категорію та мати ієрархічну структуру.
        У файлі ir.model.access.csv потрібно надати права на доступ до доданих моделей для цих двох груп користувачів.
        Додайте у модуль не менш ніж 2 правила доступу.

    ==========================
    "Магазин одягу" cloth_shop
    Довідники -
    cloth.brand — Бренди (Назва, Країна, Логотип).
    🆕 cloth.collection — Колекції (Сезон, Рік, Тема).
    🆕 cloth.size — Довідник розмірів (XS, S, M, L, XL).
    Документ -
    "Надходження товару" з якого формується картка товару, якщо товар новий,
    або оприбутковується існуючий товар.
    Один й той самий товар має однаковий "Артикул".
    Реквізити товару в надходженні - артикул, назва, бренд, розмір, колекція, кількість,
    ціна закупки, роздрібна ціна.
    В документі повинна  бути кнопка розрахунку роздрібної ціни.
    РОзрахунок - помноження ціни закупівлв на коефіцієнт. У довіднику "Коефіцієнти націнок"
    використовуємо виміри - Бренд,Колекція та задаємо на них коефіцієнт.
    Без розрахованої роздрібної ціни документ можна записати, а не провести.
    Після проведення документу товар стає на залишки магазину. І доступен для замовлень.

    Документ
    "Замовлення товару" має клієнта (прізвище, телефон, е-маил)
    дата замовлення, таблиця товару,
    загальна сума замовлення з урахуванням знижки клієнта,
    адреса доставки.
    Замовлення повинно мати статуси - в роботі, відправлено, отримано,
    відмова клієнта., скасовано
    Статус відправлено - знімає товар з залишку магазину,
    відмова клієнта., скасовано - повертає товар на залишки

    В картці клієнта можна встановити персональну знижку

    Звіт по залишкам та обороту товару.
    ===================
    📂 Структура модуля (Моделі даних)
1. Довідники (Master Data)

    cloth.brand (Бренди): name (Char), country_id (Many2one -> res.country), logo (Binary).
    cloth.collection (Колекції): season (Selection: Весна/Літо, Осінь/Зима тощо), year (Char), name (Char - Тема).
    cloth.size (Розміри): name (Char - XS, S, M, L, XL).
    cloth.markup.coefficient (Коефіцієнти націнок): brand_id (Many2one), collection_id (Many2one), coefficient (Float). Ключ унікальності: Бренд + Колекція.
    res.partner (Клієнти): Спадкування стандартної моделі Odoo. Додається поле personal_discount (Float) — персональна знижка у %.

2. Картка товару та Облік залишків

    cloth.product (Товар): sku (Char - Артикул, унікальний), name (Char), brand_id (Many2one), size_id (Many2one), collection_id (Many2one), qty_available (Integer - Залишок), purchase_price (Float), retail_price (Float).
    Документ "Надходження товару" (cloth.receipt)
    Документ "Замовлення товару" (cloth.order)

    Повна модель розробки модуля cloth_shop
    
1. Моделі (5 нових + 2 наслідування)

    🆕 cloth.brand — Бренди (Назва, Країна, Логотип).
    🆕 cloth.collection — Колекції (Сезон, Рік, Тема).
    🆕 cloth.size — Довідник розмірів (XS, S, M, L, XL).
    🆕 cloth.product — Власна модель товару (Назва, Ціна, Стан, зв'язок з Брендом та Розмірами).
    🆕 cloth.order — Замовлення (Клієнт, Дата, Сума, Рядки замовлення).
    🧬 product.template — Наслідування: додаємо "Склад тканини" та "Інструкції з догляду".
    🧬 res.partner — Наслідування: додаємо "Улюблений бренд" та "Розмір клієнта".

🎨 2. Інтерфейс (Представлення)

    Tree & Form: Для всіх моделей.
    Kanban: Для cloth.product (картки з фото товару).
    Pivot & Graph: Для cloth.order (аналітика продажів за періодами).
    Search: Для товарів (фільтрація за брендом, станом "У продажу" та еко-складом).
    Меню: Власне верхнє меню "Магазин одягу" з іконкою одягу.

🛡️ 3. Доступ та Безпека

    Групи:
        Clothing User (може створювати замовлення та бачити товари).
        Clothing Admin (керує брендами, налаштуваннями та бачить звіти).
    Правила (Rules):
        Користувач бачить лише власні замовлення.
        Користувач бачить лише товари у статусі "У продажу".
    ir.model.access.csv: Повний перелік прав для кожної моделі.

⚙️ 4. Функціонал та Логіка

    Візард: clothing.order.report.wizard — вікно вибору дат для формування друкованого звіту.
    Звіти: PDF-звіт "Чек замовлення" або "Картка товару" з брендом та складом тканини.
    Тести: Python-тести для перевірки:
        Чи не можна активувати товар без ціни.
        Чи правильно працює автоматичне визначення "Еко-товару".
    Демо-дані: XML-файл з прикладами 3 брендів, 3 колекцій та 3 товарів.
